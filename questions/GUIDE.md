# Разбор пакета и вопроса

Порядок для агента. Сначала пакет, потом каждый вопрос. На выходе разбор, который принимает `corpus.realia.parse` и кладёт `corpus.store`. Модули сами модель не вызывают.

Длинные примеры классов лежат рядом: ходы в [MOVES.md](MOVES.md), приёмы и формы в [TECHNIQUES.md](TECHNIQUES.md), реалии в [REALIA.md](REALIA.md), таблицы базы в [STORE.md](STORE.md). Здесь порядок работы и правила, по которым выбирается тип записи.

Списки ниже уже встретились. Новое имя всё равно записывается как есть: новый ход, kind реалии, приём, тип свойства, имя связи, область, тип источника, язык, тема источника, формулировка формы. Закрытого списка нет.

## Два прохода

Пакет читается целиком, вопрос за вопросом. Концепция тура видна по преамбуле и по комментарию последнего вопроса. Мета — любой вопрос, который опирается на один из предыдущих: в пределах тура, а если блок одних редакторов шире тура, то во всём этом блоке. Одиночная карточка их не восстанавливает: если на входе один вопрос, эти два хода ставятся лишь когда его собственный комментарий прямо на них указывает.

Редакторы берутся из каталога, не из текста. Редакторы тура, а если их нет — редакторы пакета. Их передают в `corpus.store.put` вместе с разбором.

## Проход по пакету

1. Разложи пакет на туры. У вопроса есть `tour_number` и `question_number`.
2. Отдельного поля преамбулы нет. Ищи её в комментарии первого вопроса тура и в комментарии, который на неё ссылается.
3. Прочитай комментарий последнего вопроса тура. Общая закономерность тура обычно написана там или в преамбуле.
4. Если одна закономерность помогает брать вопросы тура, каждому такому вопросу добавь ход `concept`. Собственный ход вопроса при этом остаётся: концепция добавляется к нему, а не заменяет его.
5. Для каждого вопроса прочитай комментарий. Если ответ собирается из более раннего вопроса того же тура, добавь ход `meta`. Предыдущим может быть любой вопрос тура до этого, не только соседний. Связь `meta` соединяет реалию этого вопроса с реалией того.
6. Если один блок редакторов покрывает несколько туров, предыдущий вопрос ищется во всём блоке, в том числе в более раннем туре того же блока.
7. Дальше каждый вопрос разбирается по алгоритму ниже. Предыдущие вопросы блока уже прочитаны, поэтому мета и концепция известны.

## Проход по вопросу

Вход: текст, ответ, зачёт, незачёт, комментарий, источник, редакторы.

1. Область вопроса. Одна или несколько: искусство, литература, история, новости, мемы или новая. Область — про тему вопроса. Ходом она не является.
2. Источники. Сырая строка остаётся в каталоге. Пункты «1. … 2. …» разложи на отдельные источники. У каждого пункта: дословная ссылка, тип, язык, тема. Тип: книга, статья, сайт, фильм, энциклопедия, телепередача, газета или новый. Язык страницы или издания — своим полем. Тема источника и область вопроса — разные поля: вопрос про мем может опираться на книгу по истории.
3. Приёмы. Отметь, какие следы сборки есть в тексте. Приём не шаг взятия и не запись базы. Имя, которое приём всё-таки называет, остаётся реалией.
4. Формы. Для каждого требования к виду ответа сохрани пару: формулировка, как она стоит в вопросе, и ответ, который под неё подошёл. Форма свойством реалии не становится.
5. Реалии. Выпиши каждое явно названное имя и каждое имя, которое называет ход. Заготовки «ИКС», «АЛЬФА», «ПРОПУСК», «ПЕРВЫЙ» именами не являются.
6. Предложения. Каждое предложение, которое что-то утверждает о реалии, положи ровно в одну запись: свойство, факт или связь.
7. Ходы. По порядку шагов, которыми берётся ответ. У хода есть записи, которые он читает, и реалии, которые он называет. Две улики одного класса, сходящиеся к одному ответу, — один ход.
8. Сдай разбор в `parse`, затем в `put` вместе с редакторами. Повторная запись того же `question_id` заменяет его строки.

## Ходы

Ход — шаг взятия. У него есть место в цепочке, запись, которую он читает, и реалия, которую он называет. Следующий шаг берёт то, что дал предыдущий.

| Код | Когда это он |
| --- | --- |
| `word` | буквы, морфемы, звучание или внутренняя форма слова сами дают ответ |
| `precedent` | дата, место, имя или деталь сужают рассказ до одного случая |
| `property` | черты достаточно, чтобы назвать носителя, и черта живёт вне одного эпизода |
| `parallel` | у двух рядов одна схема, известный ряд называет неизвестный |
| `formula` | в готовой цитате, названии, девизе или термине вынуто слово, его возвращают |
| `literal` | идиому читают как физическое событие или событие называют идиомой |
| `function` | тот же предмет используют не для той работы, для которой он сделан |
| `count` | число делят на готовый перечень или собирают ответ из такого перечня |
| `school` | ответ уже лежит в форме вопроса: ударение, размер, раскладка бланка, слова, которые велено найти в тексте |
| `meta` | ответ собирается из предыдущего вопроса этого тура или, если блок редакторов шире тура, из предыдущего вопроса блока |
| `concept` | одна закономерность тура помогает брать его вопросы |

`school` — про форму этого вопроса. `meta` — про предыдущий вопрос тура или блока редакторов. `concept` — про тур целиком, её пишут в преамбуле или в комментарии последнего вопроса. Школой мету не называют.

`property` читает только свойства. `precedent` читает только факты одного эпизода. Остальной известный код читает связь своего `kind`. Неизвестный код тоже записывается: он читает те записи, без которых ответ не собрать.

## Приёмы

| Имя | Что это |
| --- | --- |
| упаковка | объявленная дырка: «назовите ИКС», «ПЕРВЫЙ и ВТОРОЙ», «заполните ПРОПУСК», «в вопросе есть замена» |
| проверка | род и число заготовок, которыми различают два кандидата внутри одного вопроса |
| подмена | на месте слова ответа стоит более редкий синоним |
| окраска | слово оставлено в своей фразе и выбрано так, чтобы намекнуть на сторону ответа |
| костыль | вставленный чужой кусок: он направляет или срезает вторую версию и сам ответ не называет |

Ход начинается там, где становится ясно, чем заполнить дырку. Проверка ответ не называет. Подмена и окраска — разные приёмы: подмена стоит на месте ответа, окраска остаётся в своей фразе.

## Форма

Форма — требование к виду ответа, дословно из вопроса, и ответ, который под него подошёл.

«Два слова на парные согласные» — «сухой закон». «Соседние буквы алфавита» — «контактные линзы». «Двукоренным словом» — «авианосец». «Словом, происходящим от топонима» — «Библия». «Три слова» — «работает как часы». Новая формулировка — новая пара. Класс хода от неё не появляется.

## Реалии

Реалия — объект, который другой вопрос может назвать снова. Написание идентификатором не является. Бог Марс, планета Марс и батончик «Марс» — три реалии.

| kind | Что это |
| --- | --- |
| `person` | человек или бог |
| `group` | группа людей, народ, компания, войско |
| `thing` | вещь, животное, вещество, продукт |
| `place` | место |
| `work` | произведение, формула, термин как готовое имя |
| `event` | один эпизод, который сам можно узнать |
| `word` | словоформа |

`given` — имя стоит в тексте до хода. `yielded` — имя называет ход, в том числе ответ и промежуточный шаг. Солдаты, закрытые словом «НИХ», — `yielded`. Батончик, названный в тексте, — `given`. Локальный id не выходит за вопрос. Одинаковые имена разных вопросов в одну реалию пока не сливаются.

## Свойство, факт, связь

Одно предложение попадает ровно в одну запись.

Свойство — черта одного носителя. Её можно повторить в другом вопросе про него, без даты и без «однажды». «Слепой», «древнегреческий поэт», «время жизни известно приблизительно» — свойства Гомера. Оговорка «вероятно» остаётся в тексте. Если черта называет другую реалию, это уже связь.

Факт — один эпизод. Другие участники или другой момент делают другое событие. Ночь, когда Хаммера пустили в Мавзолей, — факт. Авторство «Илиады» фактом этой ночи не является.

Связь — устойчивое отношение минимум двух реалий. Имя связи — чем они соединены: `автор`, `размер`, `покровитель` или новое. «Гомер — автор „Одиссеи“ и „Илиады“». «Обе поэмы написаны гекзаметром»: гекзаметр — отдельная реалия, размер можно спросить, не называя поэта. Код хода на связи ставится только если ход её читает.

Выписывается и то, что ход читает, и то, что вопрос прямо говорит. Предложение, которым ответ не берётся, в базе остаётся.

## Каркас

Поля, которые ждёт `parse`. Редакторов в этом объекте нет: они идут в `put` отдельно.

```json
{
  "areas": ["история"],
  "sources": [
    {
      "citation": "Гомер. Одиссея. М., 1984",
      "types": ["книга"],
      "languages": ["русский"],
      "themes": ["литература"]
    }
  ],
  "techniques": [],
  "forms": [
    {"wording": "одним словом", "answer": "Гомер"}
  ],
  "realia": [
    {"id": "homer", "name": "Гомер", "kind": "person", "status": "yielded"},
    {"id": "odyssey", "name": "Одиссея", "kind": "work", "status": "given"}
  ],
  "properties": [
    {"id": "blind", "bearer": "homer", "type": "", "text": "слепой"}
  ],
  "facts": [],
  "relations": [
    {"id": "wrote", "link": "автор", "text": "Гомер написал «Одиссею»", "realia": ["homer", "odyssey"]}
  ],
  "moves": [
    {"code": "property", "reads": ["blind"], "yields": ["homer"]}
  ]
}
```

`yielded` называет хотя бы один ход. `given` ход результатом не называется. Связь держит минимум две разные реалии. У известного хода слой чтения свой: свойство, факт или связь того же кода.
